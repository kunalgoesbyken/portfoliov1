<Section kicker="For everyone" title="What it does">

When a team spans timezones, work gets handed over in chat threads, and nobody can tell who owns what when they wake up.

TaskFlow makes the handoff a first-class action. A timezone board shows one column per teammate with their local time, so passing a task to the next shift is a drag from one column to another. Task creation, handoffs and bulk changes are logged as events on the task, the new owner gets a notification, and handoff templates make sure the notes the next person needs are filled in before a task can move on.

Select many tasks at once to change status, priority or owner in one step. An analytics page shows who is overloaded, and the AI Shift Brief summarises everything that changed in the last day or week, so the morning catch-up takes a minute.

GitHub webhooks update linked tasks: closing an issue or merging a pull request marks the task done, and reopening an issue reopens it. It can be self-hosted with Docker. Visitors can click "Try the demo" to open a populated workspace without signing up.

</Section>

<Section kicker="For engineers" title="How it is built">

A Next.js 15 App Router app on Vercel, running in the Mumbai region next to its Supabase Postgres database. Supabase provides sign-in, the database and realtime; Prisma is the only query layer.

1. `middleware.ts` refreshes the Supabase session cookie and redirects signed-out visitors away from `/dashboard`, `/tasks`, `/analytics` and `/settings`. It does not run on `/api`.
2. Pages such as the dashboard and the timezone lanes are server components. They call `getAuthUser()` and read tasks through Prisma, so the first paint already has data.
3. After that, client components use TanStack Query against the route handlers in `app/api`. Each handler calls `requireAuth()`, validates the body with Zod and limits task queries to tasks the caller created or is assigned.
4. Prisma connects with database credentials, so access control is those `where` clauses in application code, not row-level security. Create and reassign save the task, a `TaskEvent` and any notification in one `prisma.$transaction`. Template-aware status changes go through `set-status`, which validates the template and updates the task without writing an event.
5. `useRealtimeTasks` and `useRealtimeNotifications` listen to Supabase Realtime and only invalidate the query cache. The timezone lanes also use Realtime Presence to show which teammates are online.
6. GitHub posts to a signed webhook route that updates linked tasks. `/api/shift-brief` queries recent tasks and calls Gemini. Slack has an install flow and an events endpoint.

<Highlights>
<Highlight title="Realtime without a second data path" result="Live updates always render the same joined shape as the API">
Supabase Realtime payloads carry no joined rows, so applying them directly leaves tasks without an assignee or creator. Each event is treated as a signal that invalidates the TanStack Query cache and triggers a refetch, so there is one data path instead of two.
</Highlight>
<Highlight title="Bulk changes in one transaction" result="A 50-task change is 2 writes, not 100, and they commit together">
The bulk endpoint first checks that the caller can access every selected id; one foreign id rejects the whole request. The change is a single `updateMany` plus one `createMany` for the audit trail, both inside one `prisma.$transaction`, so a failure cannot leave a change without its audit events.
</Highlight>
<Highlight title="Verified webhooks and encrypted tokens" result="Inbound calls are verified and stored tokens are encrypted">
GitHub webhooks are checked by recomputing the HMAC with a timing-safe comparison. Slack requests are verified the same way with a five-minute replay window, and Slack tokens are encrypted with AES-256-GCM before they are stored. A typed environment schema refuses to boot if the encryption key is shorter than 32 characters.
</Highlight>
<Highlight title="A self-seeding demo" result="One click from the sign-in page to a populated workspace">
The demo endpoint creates its user and seeds five teammates in five timezones on first use. Seed rows use fixed ids with skip-duplicates, so concurrent first visitors cannot create copies, and the demo password is derived from a server secret rather than committed.
</Highlight>
</Highlights>

Handoff templates store per-status required fields and allowed transitions as JSON in `HandoffTemplate.steps`, and the handlers check them before a status change. The Shift Brief builds a prompt from the caller's tasks updated in the last 24 hours or 7 days and streams the Gemini response back as server-sent events.
